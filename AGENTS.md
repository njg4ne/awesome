# AGENTS.md

Guidance for any AI agent or assistant working in this repository.

## Project Overview

This is a personal "awesome list" by **Nicholas Gardella**: a curated collection of tools and resources across several areas. It's prose in Markdown with no code or build step. It's written for people to read, mainly through GitHub's Markdown preview.

## Authorship and Voice

- Nicholas Gardella is the author and the intellectual owner of this list. All selections, opinions, and preferences belong to Nicholas.
- Agents assist with drafting and organization. The README says so openly, and this repo has nothing to hide about it.
- Don't claim credit, sign entries, or add agent names, "generated by" notes, or self-references to the content.
- Don't invent opinions, endorsements, or experiences. Only write down preferences the author has actually stated. If a rationale is missing, leave it out or ask.
- Keep the author's reservations and qualifiers (for example, "still new to it" or "wouldn't necessarily recommend").
- Don't mention the author in the list's prose. The name belongs only in the root title and the **Authorship** section.
- Write entries impersonally, as recommendations ("Podman is preferred over Docker for ..."). Never use first person, and don't refer to the author by name or pronoun. Keep it brief and plain.

## Structure

```text
README.md              # Root index: intro, contents, highlights, authorship, license
AGENTS.md              # This file
LICENSE                # CC BY-SA 4.0 legal code
<topic>/README.md      # One folder per area, e.g. development/, documents/
```

- Every topic folder has a `README.md` so GitHub renders it when someone opens the folder.
- The root `README.md` links to every topic folder in its **Contents** list.
- Each topic page starts with a `[← Back to all awesomes](../README.md)` link and a numbered **Contents** list of anchor links to its `##` sections.

## Adding or Editing Entries

1. Put the entry in the most specific topic that fits. If none fits, create `<topic>/README.md` using the existing pages as a template, and add it to the root **Contents**.
2. Use this entry format: `- [Name](https://official-site) is ... one or two sentences.`
   - Link to the official homepage first. Add `([GitHub](...))` if a source repo exists.
   - Use nested bullets for related plugins, sub-products, or notes.
3. Keep explanations short. Link out instead of explaining at length.
4. Check that every URL is real and points to the canonical source. Don't guess URLs.
5. Use relative links (`../research/README.md`) between pages in the repo.
6. Only add something to the root **Highlights** when the author asks.

## Markdown Conventions

- One `#` title per file, `##` sections, and `###` subsections when needed.
- Use `-` for bullets and `1.` for ordered lists.
- Use fenced code blocks with a language tag.
- Spell product names the way the project does (pnpm, Podman, Typst, ZotMoov, text2qti).
- No raw HTML unless Markdown can't do the job.

## Checks Before Committing

- All relative links resolve to existing files and anchors.
- External links load and point to the intended project.
- The page reads well in GitHub's rendered preview.
